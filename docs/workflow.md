# Development workflow

## Repository

- A **private** GitHub repository.
- `develop` is for daily work. `main` is what production runs and is only ever **fast-forwarded** to `develop`.

## For every change

1. Inspect the existing code, docs and tests first.
2. Implement the smallest correct change using the established patterns (services, Form Requests, enums, policies, components).
3. Add or update a **feature test** for every behaviour change, calling real routes.
4. `vendor/bin/phpunit`: must pass. Judge by the command's result, never "looks fine".
5. `vendor/bin/pint --dirty`: must be clean.
6. Update `docs/` and `CHANGELOG.md`.
7. Commit to `develop` (stage explicit paths when practical) and push.
8. Fast-forward `main` and push it:

```bash
git checkout main
git merge --ff-only develop
git push origin main
git checkout develop
```

If `--ff-only` fails, `main` has diverged. Stop and investigate. Never force-push `main`.

## Commit messages

Commit messages start with `feat:`, `fix:` or `chore:`:

```text
feat: add student exam tracking
fix: prevent counselors viewing unassigned students
chore: update deployment documentation
```

No `Co-authored-by: Claude` lines.

## Never commit

`.env`, `vendor/`, `node_modules/`, `public/build/`, storage backups, database dumps (`*.sql`, `*.sqlite`), `.claude/`, or any secret. `.gitignore` enforces most of this. Still review `git status` before committing.

## Continuous integration

`.github/workflows/ci.yml` runs on pushes to `develop`/`main` and on pull requests. It installs dependencies, builds the assets, runs `pint --test` and runs `vendor/bin/phpunit`. CI never deploys.

## Claude Code

- Project guidance for Claude Code is in `CLAUDE.md`, generated by Laravel Boost from `.ai/guidelines/tamakkun.md`. Edit the guideline file, then run `php artisan boost:update`.
- `.claude/` (local skills, settings) is never committed.
